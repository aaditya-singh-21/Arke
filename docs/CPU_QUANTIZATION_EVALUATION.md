## Experimental profile

All stages explicitly run on CPU. Whisper small uses CTranslate2 `int8_float32`. Translation uses FBGEMM dynamic qint8 linear weights and optionally quint8 embeddings with per-row floating quantization parameters; other tensors remain FP32. Official preprocessing, beam size five and configured bounds remain unchanged. Quantized embedding indices are copied contiguously without changing token values. Kokoro remains FP32, with 89 legacy WeightNorm hooks fused into fixed inference weights. Checkpoint mapping and no-grad construction avoid unnecessary copies/graphs. This profile is recorded in actual provider metadata; it is not a supported public precision option in the existing application configuration.

An explicit offline conversion creates checksummed derived weights in ignored `models/experimental-cpu/`, preserving source revisions. Runtime constructs empty learned parameters and strictly assigns cached weights, including nonpersistent TTS buffers/auxiliary tensors. Translation sinusoidal positional buffers are generated by the pinned vendor constructor's CPU formula. It restores the saved generation configuration and the internal original-object hash required by transformers 4.51.3. There is no automatic conversion, model/device substitution or fallback when cache verification fails.

The initial runtime remains torch 2.7.1+cu126, even with all inference on CPU. Accelerate 1.6.0 is scoped through the existing ignored isolated dependency directory. The source assets retain the revisions in LOADING_EVALUATION.md. Cached translation weights are 277,258,302 bytes, SHA256 `0705de837962dd5c2e17ed0a616b29c415fca98b1ef2a5fde53e66b0339999ce`; fused TTS weights are 327,299,083 bytes, SHA256 `07fd0ce9e1ad46894c1a838c2bb50abae20c8fbf3acea8b38b30b6eb4c602c92`.

An additional runtime comparison explicitly uses official torch 2.7.1+cpu (Windows cp311 wheel, 206 MiB download) in `.cache/investigation-torch-cpu`, scoped ahead of the unchanged environment through PYTHONPATH. This keeps the same PyTorch release and cached weights. The loader permits the exact CPU/CUDA build comparison only with an explicit experiment flag and records the actual imported version and absent compiled CUDA runtime. Cross-build cache compatibility is experimental and requires numerical verification. This is not an application dependency/default change. [Official pinned CPU wheel instructions](https://pytorch.org/get-started/previous-versions/#v271).

## Reproduction and status

Local ignored diagnostic scripts, not supported application CLI commands. Do not overwrite evidence. Use a fresh output directory and the scoped dependency path:

```powershell
$env:PYTHONPATH=(Resolve-Path .cache/investigation-accelerate).Path
.\.venv\Scripts\python.exe artifacts/cpu_quant_probe.py --cached --output artifacts/cached-cpu-probe-new
$env:ARKE_LOADING_EXPERIMENT='cached_cpu_quantized'
.\.venv\Scripts\python.exe artifacts/investigation_benchmark.py benchmark --stage pipeline --config artifacts/option5-cpu-quant-base.toml --manifest data/eval/asr-diagnostic-2/manifest.jsonl --output artifacts/cached-cpu-benchmark-new --allow-unreviewed
.\.venv\Scripts\python.exe artifacts/cpu_cache_numerics.py --output artifacts/cpu-cache-numerics-new
Remove-Item Env:ARKE_LOADING_EXPERIMENT
Remove-Item Env:PYTHONPATH
```

The optional isolated CPU-runtime comparison uses:

```powershell
uv pip install --python .venv/Scripts/python.exe --target .cache/investigation-torch-cpu --cache-dir .cache/uv --no-deps --index-url https://download.pytorch.org/whl/cpu torch==2.7.1+cpu
.\artifacts\run-cached-cpu-benchmark.ps1 -CpuOnlyTorch -Output artifacts/cpu-only-build-new
```

The ordinary environment remains torch 2.7.1+cu126. The launch script restores prior environment variables. CPU inference does not use CUDA; low device-wide VRAM reflects background GPU use, not GPU inference. The first download attempt was blocked by sandbox network access (Windows socket error 10013); an approved scoped download succeeded, recorded in `option5-cpu-torch-install-authorized.txt`.

The conversion script deliberately refuses an existing asset directory and is not a supported model setup command. Original model receipts remain unchanged. No model weights, caches or artifacts are committed. Numerical fingerprints/tolerances cannot establish Hindi intelligibility, bilingual adequacy, critical-detail preservation or acceptable quantization quality. Clean/noisy human WER, quality scores, acoustic response, disconnected hardware operation, and 30 microphone turns remain pending. No configuration is accepted until full memory and appropriate human/hardware gates pass.
